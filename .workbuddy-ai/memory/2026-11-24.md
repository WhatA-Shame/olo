## 杯杯菇（mushroom）蒙皮撕裂 + 侧滚方向 修复

### 撕裂真正的根因（上一次的判断是错的）
- 模型是 **70 个互不相连的碎片**（纸片/低模风格，`tools/dump_parts.mjs` 可查）。
- 撕裂只可能发生在**同一碎片内部**：同一碎块的相邻顶点被分到完全不同的骨骼，碎块被拉开。
- 原版权重把整片左侧身体面板（y 0.26~1.05，含臀部）判给了 `L_Thigh`，跑动时大腿一摆就撕。
- 上一次的"Twist 合并 + 相邻骨骼才允许双骨混合"没用，因为**逐顶点**独立选骨骼对，
  同一碎块里 A 点选 (Thigh,·)、B 点选 (Clavicle,·)，边界直接裂开。

### 修法：`tools/reweight.mjs`（不需要原始 GLB）
1. 按连通块分片，统计每片原版权重的骨骼票数 → 判定"族"（head/armL/armR/legL/legR/torso）。
2. 每片**只允许本族相关骨骼**参与（菌盖片绝不会被手臂骨抢走）。
3. 权重 = `1/(到骨骼线段距离)^2`，取前二归一化。
   **纯几何权重是位置的连续函数 → 同一碎块内不可能出现突变 → 结构上不可能撕裂。**
- 结果：Head 1693（菌盖刚性）/ Pelvis 202（身体）/ 大腿只剩 108、36。
- 脚本**只能跑一次**（族判定依赖当前 skin），重跑前先 git checkout 网格模块。

### 侧滚方向
- 错的表现：`R.add(rootJ, 90, angle, 0)` = 先 Rx(90) 把身体前倾放倒，再绕自身头脚轴自转
  → 头顶朝前进方向、像钻头钻地。
- 正确做法：只留 `R.add(rootJ, 0, angle, 0)`（绕模型 Y 轴）。
  `bindQ[root] = Rx(-90°)`，模型 -Y → 世界 +Z，所以**绕模型 Y 转 = 绕前进轴转**，
  肚子朝向恒定朝前，头在竖直平面里划圆 = 侧手翻。旋转中心抬到 y≈0.65 绕身体中部转。
- 通用结论：要让某个朝向在旋转中保持不变，就绕那条法线轴转。

## 牛伟（chijin）待机姿势 + 握斧（已修）
- **根因 1：待机是"T 姿势"** —— `bNw()` 待机/受击分支只 `rest(R)`，而外部骨架的绑定姿态上臂几乎是横着出去的（A 姿），
  这套 GLB 的 5 个片段里没有 idle，所以直接回绑定姿态就是外张。
  修法：`armsDown(R)` = `R.add(upperRJ,0,0,+26)` / `R.add(upperLJ,0,0,-26)`，再给手腕回正 12°。
  **手腕必须回正**：不回正的话斧头跟着胳膊一起转 26°，柄底会甩到裆下甚至穿地（实测柄底 y=-0.011）。
- **根因 2：斧头不在拳心** —— 柄轴原来长在手骨点（腕关节）上，跟拳头差 0.08~0.1。
  修法：`HX = bindWorld[hand]*1 - 0.05`、`HZ = ... + 0.03`，让柄轴穿过拳心。
  注意：**手的 2 骨骼权重顶点是散开的**（31 个点 x 从 -1.32 到 -0.91），质心不可靠，最后是靠渲染截图定的偏移。
- 顺带把柄上移 0.26（`botY=HY-0.46`、`topY=HY+0.92`）：手臂放下来以后柄底会戳地、斧刃会挡住前臂。
  上移后握点落在柄的 29% 处，刃面离前臂 0.30，斧刃顶到 y≈2.0（和牛角齐平，不挡身体）。
- 离线探针 `tools/_axecheck.mjs`：按引擎 FK 复算「手臂角度 → 拳心/柄轴/刃面位置」，输出垂距与刃面到手臂的最近距离。
  FK 与 `bindWorld` 会差一个**常量根偏移** `(0.156, 0, -0.108)`，补上就完全吻合（这是之前 FK 探针"误差 1.37"的真正原因）。

## herocheck 在无头浏览器里的时间陷阱（重要）
- **无 vsync，模拟时间跑得比真实时间快得多**（2 秒的引导几百毫秒就走完了），
  所以任何"sleep 到引导中间采样"的断言都会测到引导结束之后。改法：不要靠墙钟，改成确定性检查

- `u.mana = 99999` 会被下一帧夹到 `maxMana`，导致"技能消耗法力"读到 1406→1410（反增）。改成 `maxMana*0.7` 留余量。

## 武器握点：必须写进「手骨局部空间」，不能按世界坐标硬偏移
- 症状：斧柄/剑柄看起来**粘在手背上**、或者浮在掌外侧，手指根本兜不住。
- 根因：握点原来是 `bindWorld[hand] + 世界偏移`。手的局部轴在世界里是斜的

  牛魔更隐蔽：世界 -0.191 → 局部 +0.102，正好嵌在手掌厚度中间偏掌背。

## 立绘/模型白模的真正根因（两个，缺一个都还是白模）
上一节「新英雄立绘白模」只修了"解码晚 + 缓存"，**没修完**。牛魔一直是白模，原因是：

1. **牛魔两套网格模块漏了预热行**。`45-niuwei-mesh.js` / `45-mushroom-mesh.js` 底部都有
   `if (typeof document !== 'undefined') setTimeout(() => heroMap(), 0);`，
   `45-niumo-mesh.js` / `45-niumo2-mesh.js` **没有**。少了它，贴图要等第一次建模才去解码，
   而选将台的立绘在那之前就已经渲染并缓存进 `j1` 了。`glb2hero.mjs` 的模板里也没有这行 →
   重新生成还会漏。已补进模板。
2. **占位图是 1×1，而真图是 512×512 —— 这是最隐蔽的那个**。
   three 的 `WebGLTextures` 走 `texStorage2D`（**不可变存储**）：第一次上传按占位图尺寸分配，
   之后把 `tex.image` 换成真图只走 `texSubImage2D`，尺寸对不上就被整张丢弃，
   模型永远停在占位色。CPU 侧 `tex.image` 明明是 512×512 的暗色图集，
   但 GPU 上还是那张 1×1 占位图 —— 所以"换 tex.image + needsUpdate"看着毫无反应。
   修法：**占位图与真实贴图同尺寸**。生成器从 JPEG/PNG 头里读出宽高写成 `TEX_W/TEX_H`，
   占位 canvas 用同一尺寸；四个网格模块同步。

### 排查方法（下次别再靠猜）
- 判定"贴图到底有没有参与着色"最省事的办法：**运行时把 `uMapOn` 置 0**。
  画面不变 = 贴图没生效；画面变成纯白 = 贴图一直在正常工作（`mix(vec3(1.0), texel, uMapOn)`）。
- **把 GPU 上的贴图读回来**：`renderer.properties.get(tex).__webglTexture` 拿到 GL 纹理，
  挂到临时 framebuffer 上 `readPixels(0,0,1,1)`，就能看到 GPU 里到底是什么内容
  （这次读到 `[23,23,23]` 说明上传的是暗色图集，而不是我怀疑的占位色）。
- **`gl.getUniformLocation(prog,'xxx')` 返回 null = 这个 uniform 被编译器优化掉了**，
  也就是"shader 源码里没用到它"。这条能立刻区分"uniform 值不对"和"源码根本不是我以为的那份"。
- **踩过的坑：`cp 备份 目标 && node -e "..."` 里如果 node 的脚本有反引号，
  整条命令会解析失败，`cp` 也不会执行**。这次因此让一个"直接输出贴图色"的测试补丁
  在构建里残留了好几轮，害我一直在错误的前提下推演。改文件用 Edit 工具，别塞进 bash 一行流。

### 新增回归（herocheck）
- 静态：每个 `src/45-*-mesh.js` 必须有预热行；`TEX_W/TEX_H` 必须等于内嵌贴图的实际尺寸
  （直接从 JPEG SOF / PNG IHDR 头里读）。
- 运行时：读选将台 `img[data-sf-portrait]` 的像素，量化后颜色数 <8 判为白模。
  截图上一块灰肉眼很容易放过，数颜色才是确定的。
- 现状：niumo 22 项 / chijin 19 项 / mushroom 28 项 / panyue 18 项全通过。

## 牛伟的斧头：柄方向终于对了（第三/四次被骂之后）

### 症状
用户反复说"斧头方向不对"，最后一句是"柄到底朝哪里"。之前一直按**世界坐标**摆斧头：
柄沿世界 +Y 竖直造，再把整块平移到手边。看着"竖着"，但那是"一根竖直的杆粘在手上"，
不是"被手握住的杆"。

### 量出来的真相（离线 FK 探针，不用开浏览器）
Tripo 这几套骨架的手骨局部轴在世界里的方向（绑定姿态）：
`X→(-0.90,0.44,0.02)`、`Y→(-0.44,-0.90,0.01)`、`Z→(0.02,0.00,1.00)`。
- 局部 **Y = 腕→指尖**（手指方向），世界朝下
- 局部 **Z = 拇指→小指**（握孔方向），世界朝正前方

**拳头的握孔是沿局部 Z 的**（手指卷起来抱住的就是这个孔）。
所以柄轴必须写 `+Z`。而"世界竖直的柄"换算到局部是 `(0.44,-0.90,0)` ——
和手指只差 26°，几乎平行，等于把柄从拳头里横着穿出去。这就是"怎么摆都不对"的根因。

### 定案写法
1. `handFrame(HR,j)` 从 `bindWQ` 取出手骨的三个局部轴世界方向，`handMatrix()` 拼成
   「列 = 三个轴 + 握点」的 4×4。
2. 整把斧头的顶点**全部写在手骨局部坐标里**（柄沿 +Y 造），外面套一层
   `t.g(M_AXE, () => {...})`，`M_AXE = handMatrix(HR, handRJ, 0.02, 0.16, 0) * 换轴矩阵`
   （作者系 → 手骨系：X→-X、Y→+Z、Z→+Y）。
   → 柄轴天然沿握孔，任何姿势都攥在手里（单骨 weight=1 刚性蒙皮）。
3. 待机时再给手腕 `HAND_ROLL = 90`（绕手骨 X 轴 = 掌背→掌心轴翻 90°），
   把握孔从"朝前"转成"朝上"，柄才竖起来。不翻的话柄虽然垂直手指，但会像端着长矛朝前。

### 顺手得到的结论
- **要让某根杆"永远从拳头里穿过去"，就把杆轴写在握孔轴上（局部 Z），别再按世界坐标摆。**
- 动画状态下 `play()` 会用片段里的腕部四元数覆盖，所以只有待机/受击加了 `HAND_ROLL`。
  刚性挂接保证任何姿势下柄都穿过握孔；跑动时柄接近水平（片段自带的腕姿），是"横扛着跑"，
  不是脱手 —— 想改成竖着扛得动片段，不是改挂点。
- 离线量方向的成本 ≈ 0：`node tools/_shaftaxis.mjs` 那类脚本几秒出结果，
  比开无头浏览器截图快一个数量级。查"朝向/角度"这类问题优先用 FK 算，别先截图。

### herocheck 新增
- `--crop=x,y,w,h,scale`：战场截图自己指定裁切框放大。战场相机是固定俯视，
  英雄基本钉在屏幕 `(350,170)` 附近，`--crop=200,40,340,300,5` 就能把斧头看清。
  试过用 `renderer.worldToScreen` 动态算英雄屏幕位置，CDP 里拿到的是空 rect（返回 0,0,false），放弃。

## 程序化动作库 + 牛魔的剑（同一天后半段）

### 先说一个把结论带偏的错误：欧拉顺序
`sw.add(j,x,y,z)` 内部是 `q * setFromEuler(x,y,z)`，three 的默认 'XYZ' 是 **R = Rx·Ry·Rz**。
我上一轮写离线探针时按 **Rz·Ry·Rx** 算，于是得出"牛魔 T 姿下手腕怎么转柄都竖不起来、最优差 56°"——
**错的**。按正确顺序，牛魔的 `armsDown(74) + 手腕 Rx(90)` 待机柄倾角只有 6°（跟牛伟的 3° 一样）。
教训：**探针的欧拉顺序必须和引擎一致**，否则后面所有推理全建在错前提上。
（工具 `tools/_posetest.mjs` 里的 `qEuler` 已经按 Rx·Ry·Rz 写死。）

### 外部骨架只有 5 段片段，劈砍/旋身/咏唱只能自己摆
`chop` 实测是**水平横扫**（斧尖在前后方向扫 1.8 米、柄与竖直夹角全程 64°~104° = 接近水平），
`dance_05` 是跳舞，`box_03` 是拳击。所以"举过头顶劈下来"没有任何片段能用。
新建 `src/26-pose.js`：`chopPose` / `spinPose` / `chantPose`，纯旋转叠加，调用前用 `rest()`（+`armsDown`）铺底。

### 手骨局部轴（两套骨架一致，用 bindWQ 实测）
- 上臂/前臂/手：**Z ≈ 世界正前方、Y = 沿骨骼方向、X = 竖直平面内垂直于骨骼**
  → 绕 X 转 = 手臂在"前—下"竖直平面里抡（正值往前上方抬）；绕 Z 转 = 侧向抬/收（armsDown 用的就是它）
  → 手的局部 Z 是握孔，绕手的 X 转 = 武器在竖直平面里翻
- 根骨骼：bindQ = Rx(-90°)，局部 **Z = 世界竖直向上**；`pre(root,0,ang,0)` = 绕竖直轴转（旋身用这个）
- **牛魔是 T 姿**：上臂的局部 X 轴几乎就是世界竖直方向，绕它转 = 手臂在**水平面**里往前甩，
  正好用来摆"举剑在身前"的施法姿势（咏唱就是这么解的）。

### 手腕角度别手调，反解
柄与竖直的夹角 ≈ `tilt0 - (上臂X + 前臂X + 手腕X)`（牛伟 tilt0≈3°、牛魔≈6°）。
所以 `chopPose` 直接给"想要的柄倾角"（蓄力 -18°、砍到底 100~122°），反解出手腕该转多少。
手调 `cock/snap` 那种写法会跟手臂角度互相打架，改一个另一个就废。
另外牛魔的收势要额外给手腕绕局部 Y 一个 `yaw:-50`，否则剑是甩到身体侧面而不是身前 —— 这是数值搜出来的。

## 原版角色皮接入（「搞怪卡丁车」20 个模型）

管线（`node tools/kartbuild.mjs` 一条命令全跑）：
1. `.kart/entry.js` → esbuild 打包 `bundle.js`（模型类用 canvas 画贴图，只能在浏览器里跑）
2. `tools/kartexport.mjs`：python http.server 8791 + 无头 Chrome CDP 9331，调 `window.__kartExport(i)`

3. `tools/glb2kart.mjs`：GLB → `dist/kart/<id>.bin`，量化自描述数据块
4. `src/47-kart-decode.js` 解码 + `src/47-kart.js` 的 `KART_SPECS` / `preloadKart`

关键经验：
- 这批是**节点动画**不是蒙皮网格（没有 skin/JOINTS_0）。所以**节点层级直接当骨架**，
  每个零件顶点权重 1 绑自己那根骨——不用重算权重，也不会撕裂。
- **骨索引必须 u16**：多脚纸箱 304 根骨，u8 截断到 255，2010 个顶点绑错骨会散架。
- **贴图色要 sRGB→线性**再写进顶点色（`rawMesh` 里 `m.col` 逐顶点用，之前只认整体 `color`，烘好的贴图色被丢掉）。
- **`def.height` 是"声明身高"不是几何高度**：渲染器把 `height*scale*Z` clamp 到 `[3.05,3.55]`，
  `scale` 会被约掉，所以最终大小只由 `height` 决定。填真实高度 → 趴着的蛤蟆横向铺成 8 米宽。
  正确写法 `height = 3.05/k`，`k = min(3.15/rawH, 2.8/rawW, 1.6)`。
- 这批模型自带朝向就是 **+Z**（蛤蟆的舌头在 z=+1.48，熊猫摩托前轮在 +Z），和引擎 forward 一致，不用转。
  选将台相机在 `+Z`（`32-ui.js` 的 `T.position.set(C, mt+rt*0.12, rt)`），所以模型正面朝观众——**别再怀疑朝向**。
- `.bin` 不进 bundle：20 个共 16MB，会让首页 6.5MB→22MB。走 `fetch` + `registerModel()` 动态登记，
  `dist/` 和 `modular/` 两种入口各试一条路径。
- 花名册从 7 张变 27 张，卡片原来 `flex:1` 平分高度会挤成一条条 → 改成固定高度 + `overflow-y:auto`。
  点卡片前要 `scrollIntoView`，否则坐标点空。

回归：chijin 20 项 / panyue 18 / fengling 18 全通过；`--skin=frog/boxman/panda/scallion` 均能进对局放技能。

### 关键经验：立绘自动构图（`fitPortrait`）
- 手调的 `dist/drop` 对 20 个形态各异的模型**不可能都合适**：蛤蟆顶到边、史莱姆缩成一小坨、
  大脚牛头顶被切、杯杯菇四周全裁。**量像素比猜参数可靠**。
- 做法：先按 `l.dist * 1.7` 渲一帧（**故意拉远**，被裁掉的话包围盒偏小、会越量越往里缩），
  `drawImage` 到 2D canvas 读 `getImageData` 的 alpha>24 包围盒，反解：
  `dist = max(bw,bh)/(0.86*0.4254)`（fov24° → 可见边长 = 0.4254×dist），
  再把包围盒中心换算回世界坐标当 lookAt。迭代 2 次收敛（透视误差）。
- **只对占位皮启用**（`if (sp)`）：正式英雄那套 `fB` 是手调过的，别动。
- `preserveDrawingBuffer` 必须开着才能 `drawImage` 读回渲染结果 —— 已经有。

### 关键经验：.bin 格式补上"统一缩放"（挤压力道全丢在这）
- 卡丁车这批动作的挤扁/拉长**全靠节点 scale**（死亡那段是 0.52~1.75 的脉动），
  以前每关节每帧只存 `t.xyz + q.xyzw` 7 个数，scale 直接丢了 —— 动作看着又僵又假就出在这。
- 现在每关节每帧 8 个数，第 8 个是**三轴几何平均**的统一缩放（引擎姿势 `sw.s` 只支持一个标量）。
- **必须存 `animScale / restScale`**，不能存绝对值：动画里的 scale 是节点绝对缩放，
  而引擎的 `s` 是乘在子骨偏移上的系数（静置=1）。存绝对值得话静置姿态就会变形。
  归一化之后静置那一刻 s≈1，立绘和以前一模一样（对比过 20 宫格）。
- 量化 i16 ×10000，±3.27 上限；青蛙有几段会顶到上限（restS 小的骨），目前看着没炸。
- `sw.s` 只影响**子骨偏移**，不改顶点大小（刚性单骨蒙皮），所以它是"骨长变化"不是"顶点缩放"，
  效果上等于整段身体伸缩——对这些一节一节的卡通角色反而合适。
