# 装备系统与定价模型

51 件装备，三档：**小件 150–850 / 中件 880–1060 / 大件 1750–3430**。
中件由 2 件小件合成，大件由 2 件中件合成；凑齐组件再买成品，只付差价。

## 一、定价模型

不凭手感标价。把每个属性折算成"等效生命(EHP)"或"等效普攻 DPS"，在**同一个参考站桩点**上比较，
再统一换算成金币。参考点取 **等级 10、0 装备的平均英雄**（7 个英雄取平均）：

```
生命 6009   护甲 276   魔抗 128   物攻 262   攻速 1.00   暴击伤害 2.0
```

公式全部来自引擎 `src/43-data-3.js`，不是另编一套：

| 机制 | 引擎实现 |
| --- | --- |
| 物理/法术减伤 | `dmg × 600/(600+护甲)` |
| 攻速 | `基础攻速 × (1 + 攻速加成)`，上限 2.5 |
| 暴击 | `伤害 × 暴击伤害`（基础 2.0） |
| 冷却缩减 | `cdMax = 冷却 × (1 − CDR)`，上限 40% |
| 穿透 | `护甲 × (1 − 穿透)`，上限 80% |
| 法强 | `(基础 + 法强) × (1 + 法强%)` |

在这个站桩点上，每点属性的边际收益是：

```
1 生命  = 1.46 EHP
1 护甲  = 10.0 EHP   → 与生命等价价 6.86 金
1 物攻  = 0.685 DPS
1% 攻速 = 1.795 DPS
1% 暴击 = 1.795 DPS
1% 穿透 = 0.565 DPS
```

### 单价表（金币 / 1 点）

| 属性 | 单价 | 说明 |
| --- | --- | --- |
| 生命 | 1.0 | **锚点**，1 生命 = 1 金币 |
| 护甲 | 4.2 | EHP 折算值 6.86 打 6 折：护甲只挡物理，实际覆盖面约六成 |
| 魔抗 | 3.9 | 同上，比护甲再便宜一点（法师位少） |
| 物攻 | 15 | 锚点 |
| 法强 | 9 | 0.6 × 物攻 |
| 法力 | 0.5 | |
| 攻速 | 1600 / 1.0 | 每 1% = 16 金 |
| 暴击率 | 1600 / 1.0 | 每 1% = 16 金 |
| 暴击伤害 | 1200 / 1.0 | 没有暴击率时几乎不产生价值，所以打折 |
| 吸血 | 3000 / 1.0 | |
| 护甲穿透 / 法术穿透 | 1600 / 1.0 | 同上，单独存在时是废属性 |
| 冷却缩减 | 2600 / 1.0 | 封顶 40%，越接近上限越不值钱 |
| 法强% | 1800 / 1.0 | |
| 移速 | 500 / 1.0 | 草鞋锚点（250 金 = 0.5 移速） |

### 目标效率

```
小件  100%   组件不亏不赚，否则玩家会想办法跳过它们
中件  102%   合成让 2%，鼓励攒件
大件  108%   再白送一件被动，作为"攒够钱"的正反馈
```

装备价值 = Σ(属性 × 单价)，**被动不计价**（被动就是买大件的理由）。
现有 13 件大件的**售价保持不变**，只把属性调到 108%；新增 4 件大件落在 2900–3430。

## 二、怎么改

所有装备只在 `tools/itemdesign.mjs` 里定义一次，改完两条命令写回源码：

```bash
node tools/itemdesign.mjs            # 打印三档装备 + 效率，检查有没有越界
node tools/itemdesign.mjs --emit     # 生成 tools/_ln.js
node tools/splice-items.mjs          # 替换 src/33-data-2.js 里的 ln
node tools/build.mjs                 # 打包
```

`node tools/itembalance.mjs` 直接读**线上源码**算效率，改完随时复查。

### 加一件新装备

1. 在 `tools/itemdesign.mjs` 的 `ITEMS` 里加一条，`tier` 决定定价档位，`from` 写合成路径（可省）。
2. 不给 `cost` 就按模型自动定价；给了 `cost` 就按你给的价格算效率，越界会报错。
3. **新装备必须有图标**：`src/34-ui-2.js` 的 `tHx` 里把它指到一个同类旧图标上
   （`tH` 里每个 id 是一件手绘 SVG，30 多件挨个画不现实，先复用同类形制、换配色）。
4. 想进推荐出装，再改 `src/02-data.js` 里对应英雄的 `build` 数组。

### 被动的限制

被动 id 在 `src/44-data-4.js` 的 `ql()` 里注册，一共 7 个：
`execute_bonus` `onhit_magic` `spell_slow` `cripple_aura` `spell_shield` `regen_ooc` `thorns`。
`rS()` 会**按被动 id 去重**——同一个被动的两件装备只生效一次。所以新装备要么复用已有 id，要么无被动。

## 三、合成怎么算

`src/43-data-3.js` 的 `cS()`：

1. `Sk(unit, id)` 先看背包里有没有 `from` 列出的**全部**组件；
2. 凑齐 → 吃掉这些格子，只扣 `cost − 组件总价`，成品放进第一个空出来的格子；
3. 没凑齐 → 走老路（鞋子按 70% 折价替换，其余找空格付全价）。

`Gf()` / `zm()` 同步改了，所以商店卡片上的价格、`还差 X 金币`、自动出装的购买时机
都会自动按"差价"算，不需要另写一套。

回归测试挂在 herocheck 上：

```bash
node tools/herocheck.mjs panyue --shop        # 买小件 → 合成中件 → 出售 → 鞋子合成
node tools/herocheck.mjs panyue --shop --shots  # 顺带截商店界面
```
