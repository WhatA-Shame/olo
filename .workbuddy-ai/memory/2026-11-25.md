## 三轴缩放：让卡丁车原版动作真正形变（用户："你这模型不能形变吗"）

- **根因**：原版卡丁车动画的挤压/拉伸在节点 `scale` 上，而且**三轴独立**
  （实测轴向比中位 1.26、p90 2.07、最大 13.29）。上一版 `.bin` 只存一个几何平均标量 `s`，
  "压扁同时横向变宽"被抹平 → 看着不会形变。
  第二个坑：缩放原本乘在**世界轴**上，转过的零件会往错方向压 → 就是"拉断"的来源。
- **改法**（一条链路全打通，缺一环就白改）：
  1. `tools/glb2kart.mjs`：每关节每帧 8 → 10 个数（`t.xyz + q.xyzw + s.xyz`），存 `animScale/restScale`；
     `restS` 也改三轴。
  2. `src/47-kart-decode.js`：同步 10 个数。
  3. `src/47-kart.js` `kartDef`：顶点预变换到骨骼局部空间
     `v_local = R(bindQW[j])⁻¹·(v_bind − bindWorld[j])`（每顶点单骨，精确），
     `rig.localVerts = true`；`playClip` 步长 8→10、写三个分量。
  4. `src/25-render-9.js`：`sw.s` n×3 + `scale3()`；`solve()` 分轴乘父骨缩放；
     `bU.ws` n×3；`pack()` 每骨 12 个数（3 texel），新增 `localVerts` 快路径（ps=wp、q=wq）。
  5. `src/15-render-4.js`：骨骼纹理 `bones*3` texel；`boneXf` 多吐一个 `vec3 sc`；
     顶点 `ps + qrot(q, position*sc)`，法线按 `S⁻¹` 变换；描边宽度用三轴几何平均。
- **顺手修**：`src/30-core-9.js` 里 6 处 `S.s[骨]`（当标量读）改成 `S.s[骨*3]`，否则读到别的骨的 x 分量。
- **验证工具**：`node tools/_kartdeform.mjs dist/kart/xxx.bin [clip...]` —— 离线 FK 算包围盒与边长拉伸，
  `--old` 还原几何平均版对比。大肥蛆：左攻击某骨 s=(1.85,1.54,1.00)、死亡 s=(1.53,0.64,1.00)，
  边长最大拉伸 1.4× 左右（= 该碎块自身的缩放），无撕裂。
- **选将台 `?anim=` 传的是状态名不是片段名**：`dead`/`cast_s1`/`emote_cheer`/`cheer`/`stop`…
  传 `die`/`attackL` 会静默退回 idle，看起来像"参数没生效"。

## "光滑水润"（用户第二问）
- 真凶不是 specular 默认值本身，而是三者叠加：
  1. 卡丁车走 cloth 类别 → `mp.x = 0` → `sAmt = max(0, vFx.x*uSpec.x)`，而 `vFx.x` = 顶点 gloss 0.34、`uSpec.x` 默认 0.9 → 高光 0.31；
  2. `mp.x == 0` 时 `hard = 0.08` → **硬边亮斑**（史莱姆身上那块小白斑实测可见）；
  3. `build()` 按位置合并平均法线 → 全平滑，没有块面。
- 已改：`gloss: 0` + `def.specular = 0`，三处批次（31-render-10 / 32-ui 两处）都传 `specular: D.specular`；
  `?gloss=1` 可还原旧外观做 A/B。
- **更深一层**：颜色是"每顶点采样一次 UV 烘成顶点色"，512×512 的贴图细节全丢了（条纹变成模糊环带）。
  `TL` 的 `uMap` 和 `def.map` 通道都是现成的，要接回原版细节只需在 glb2kart 里把每模型 1~5 张 PNG 拼成图集 + UV 重映射。
- 原版粒子：GLB 里本来就没有 —— `glbExporter.ts` 的 `是否为非导出特效节点()` 把 `Points`/`Line`/纯加色透明材质剔掉了。
  引擎自己有完整特效系统（一局发几百个特效事件），要继承得另导一轮。

## 接回原版贴图（用户选了这条）

- **glb2kart 现在输出两个文件**：`<id>.bin` + 同目录 `<id>.png`（图集）。
  一个模型 1~5 张贴图，shelf 打包成一张 NPOT 图集（不凑 2 的幂，WebGL2 支持 NPOT + mipmap，凑幂白浪费几倍显存），
  每格四周留 2px 边缘延展防双线性串格；**预留一格 4×4 纯白**给没贴图的 primitive 指过去，
  这样不用给"有没有贴图"再加一个顶点属性。
- `.bin` 头多了 `u32 texW | u32 texH`（0 = 没贴图）。顶点色只放 `baseColorFactor`，颜色交给 uMap。
  `--no-tex` 可以退回"烘顶点色"的老做法做 A/B。
- 图集 PNG 是自己编的（node 没有 PNG 编码器）：`zlib.deflateSync` + 手写 CRC32 + IHDR/IDAT/IEND，40 行搞定。
- **sRGB**：glTF 的 baseColorTexture 是 sRGB 编码，引擎顶点色/光照是线性的。新增 `uMapSRGB` 开关，
  卡丁车置 1，片元里转一次线性；原生英雄不传 → 0，行为不变。
- **占位图尺寸必须等于图集尺寸**（老坑：texStorage2D 不可变存储），所以尺寸存在 .bin 头里。
  占位色取顶点色均值，解码完成前不突兀。
- UV 超出 [0,1] 的取模（和以前烘顶点色一致），代价是雪松老师那种平铺 2 次以上的会丢重复。
- 立绘：`kartportrait.mjs` 会写回 `src/47-kart-art.js`，**烘完必须再跑一次 `build.mjs`**，否则 dist 是旧的。

## 蒙皮四骨 + 绑定姿态（大肥蛆"只有脑袋动"的终局）

用户反馈："大肥蛆还是没有扭动，只有脑袋在他妈乱动，我原作明明白白是有蠕动动作的。"

三处错叠在一起，逐个拆掉：

1. **砍成两根骨**（引擎 `aSkin` 只有 3 个分量）。大肥蛆肚子顶点普遍三骨 `0.27/0.59/0.13`，
   取最大两根归一化后相邻顶点差异被放大 4 倍。用 `_glbskin.mjs --top2` 在**完整矩阵**下复现：
   雪松老师跳舞 5.9× → 18.8×，待机 1.9× → 4.3×。**证据链闭合，不是猜的。**
   → 引擎加 `aSkin2 = (骨C,骨D,权重C,权重D)`，骨B 权重按 `1−wA−wC−wD` 反推，
   两骨顶点行为不变。`aSkin2` 必须无条件设在每个几何上（缺属性 = WebGL 默认 `(0,0,0,1)` = 骨D 权重 1）。
2. **绑定姿态用错来源**。glTF 的绑定姿态由 `inverseBindMatrices` 定义，和节点静置 TRS 不一定同姿势。
   雪松老师/大脚牛/小肥石/椰子/杯杯菇的绑定姿态是"旋转全归零的直骨"，节点静置姿态是摆好的。
   大肥蛆恰好两者一致 —— 所以这个坑一直没暴露。→ 关节骨 `bindWorld/bindWQ` 改取 `meshWorld·inverse(IBM)`。
   非蒙皮部件与关节**零重叠**（7 个模型全查过），所以不用做双份绑定数据。
3. **`localTRS()` 矩阵分支解出的是共轭四元数**：三个反对称项 `R21−R12` 之类全反号，
   等于返回逆旋转。只有 `n.matrix` 的节点走这条路（平时几乎不触发），但反解 IBM 正好走它。
   改法：先摆成行主序 `R[r][c]` 再用标准公式。

结果（最大边长拉伸，基准 = 原版 4 骨矩阵 LBS）：雪松老师 8.2→2.05×、大肥蛆跳舞 6.3×（原版 6.0×）、
大脚牛庆祝 10.4×（原版 8.2×，那条边 l0=0.0085，几乎退化）、其余全部 ≤2.5×。

**新增两个可复用工具**：`tools/_glbskin.mjs`（原始 GLB 完整 4 骨矩阵 LBS 基准，
`--top2` / `--node=N` / `--edge=a,b` / `--bones=` ），`tools/_diag3.mjs`（最差边明细：两端点的
四骨权重 + 骨骼世界变换）。**遇到形变问题先用这两个对基准，别开无头浏览器截图猜。**

`.bin` 顶点记录因此从 5 字节变 12 字节：`u16 骨A..D | u8 权重A..D`。


## 蛤蟆"站起来走时腿脚分开" —— 根因是**顶点动画网格**（不是蒙皮、不是缩放）

排查过程绕了很多弯，最后靠"红绿叠加差分图"一句话定案。记下结论和方法。

### 现象
`小加速` f10 时躯干、手臂、小腿、脚掌都对得上原版，只有**大腿整段缺失**，露出空档；
选将台放大截图里腿和身体之间是断的。

### 根因
`toad.ts` 里有一条 **"连体融合肉套"**（`创建融合肉套网格`）：4 条腿各一块 187 顶点的网格，
每帧在 CPU 上按髋点/膝点重建顶点（`posAttr.needsUpdate = true`），把躯干和腿无缝连起来。
**这份形变完全不在节点 TRS 里**（节点是恒等变换、没有任何动画通道），而 GLTFExporter 只能导出
导出那一刻的几何 —— 所以动画里这块被永久冻在待机姿态，腿一抬就断开。
`_fkcheck --parts` 报"69/70 个零件偏差 ≤0.03"是对的（GLB 内部自洽），
但它只能证明"我们忠实复现了 GLB"，**证明不了 GLB 忠实于原版**。

### 修法（已落地）
1. 导出器（`.kart/src/core/glbExporter.ts`）在 `烘焙单动作动画` 采样前后对比
   `geometry.attributes.position.version`（three 的 `needsUpdate` 会 +1），
   变了的网格名字进 `顶点动画节点名`，随返回值 → `entry.js` → `kartexport.mjs`
   写成同名 `.dyn.json`（蛤蟆是 `["节点_22","节点_40","节点_58","节点_76"]`，正好 4 块 187 顶点）。
2. `tools/glb2kart.mjs` 读到名单就把这些网格改成**真蒙皮**（`skinned += cnt` → `bindSpace` 打开），
   引擎的四骨 LBS 本来就能用。权重做法：**整块网格共用一对骨**（取网格两端最近的结构骨），
   顶点权重沿两骨连线 `smoothstep` 插值，`t=0` 在 A 骨端所以 A 的权重是 `1−w`。

### 走过的弯路（都验证过是错的）
- 逐顶点各自选最近两根骨 → 表面上的骨对跳变，管子被撕成**刀片**。
- 不排除"斑点骨"：这批模型里每个小圆点都是独立网格节点，也是骨；按距离选会选到一堆斑点。
  过滤条件：`无网格 or 自身网格 ≥80 顶点`。
- 不排除"位置重合的装饰关节"（`节点_60`/`节点_61` 和 `节点_59` 同位置），
  选出来等于只绑一根骨 → 肉套僵在髋部不跟腿走。要求第二根骨离第一根 ≥0.2。
- `smoothstep` 权重方向写反（`w` 给成 A 的权重而不是 `1−w`）→ 整条腿反向，肉套缩在髋部。

### 新增诊断手段
- `.kart/shot.js` + `shot.html`（esbuild 成 `shot.bundle.js`，从 `.kart/` 起 http.server）：
  把**原版模型**步进到指定动作/帧并渲染，和我们的 `.bin` **同机位并排**（`?i=0&a=小加速&f=10`），
  或 **红绿叠加差分**（`&diff=1`：红=只有原版有，绿=只有我们有，黄=重合）。
  这个差分图是本轮唯一能一眼看穿问题的工具 —— 比任何数值对比都快。
- `_fkcheck --parts` 只比 GLB↔.bin，**不能替代与原版的对比**。
- 注意：`d.mesh.pos` 是**烘焙后的世界坐标**，写临时脚本时必须先 `conj(bindWQ)·(v−bindWorld)`
  搬到骨骼局部空间（引擎在加载时做这一步），漏了会算出 1.8 的假偏差。

## 装备系统重做：定价模型 + 三档 + 合成

用户要求："先计算合理的装备属性价格平衡机制，然后做一批小件（150-850）作为基本合成装备，
然后做中装备（900-1450），还有补充一些大装备（2200-3800）"。

### 定价模型（`tools/itembalance.mjs`）
- 不凭手感标价：把属性折算成 **EHP / 等效 DPS**，在**同一个站桩点**比较再换金币。
  站桩点 = 等级 10、0 装备的 7 英雄平均值：HP 6009 / 护甲 276 / 魔抗 128 / 物攻 262 / 攻速 1.0。
- 公式全部取自引擎 `43-data-3.js`（减伤 600/(600+A)、攻速乘算、CDR 上限 0.4、穿透上限 0.8）。
- **1 生命 = 1 金币** 作锚点。EHP 折算说 1 护甲 = 6.86 生命，但护甲只挡物理 →
  按 6 折取 **4.2 金/护甲**、魔抗 3.9。不折的话"护甲铁靴"效率 149%，一眼假。
- 目标效率：小件 100% / 中件 102% / 大件 108%（被动不计价，被动就是买大件的理由）。
- 结果：51 件，中位 102%、平均 103%，没有越界件。
- **现有 17 件里 5 件原本就是歪的**（旧定价是手拍的）：攻速角弓 49%、反伤钉盾 69%、
  暴击吴钩 81%、破甲长戟 84%、收割斩马剑 91%。已按模型改属性，**售价不动**（不碰经济）。

### 数据管线（唯一真源）
`tools/itemdesign.mjs` 定义全部装备 → `--emit` 生成 `tools/_ln.js` → `tools/splice-items.mjs` 替换
`src/33-data-2.js` 的 `ln`。**踩坑**：`ln` 是多变量声明链的第一项（`const ln = {...}, IB = ...`），
收尾是 `}` + 逗号，拼接时别写成 `};`（会变成 `};,` 直接构建失败）。
序列化器要单独判 `Array.isArray`，否则 `from: [...]` 会变成 `{0:...,1:...}`，`Sk()` 静默返回 null。

### 合成（`src/43-data-3.js` `cS()` + `39-ui-7.js` `Sk()`）
- 买成品时先看背包有没有 `from` 全部组件：有就吃掉、只付差价，成品放进第一个空出来的格子。
- `Gf()`（价格）/ `zm()`（能不能买）同步改，所以卡片价格、"还差 X 金币"、自动出装时机
  全都自动按差价算，不用另写一套。
- 鞋子走同一条路：草鞋+布甲→护甲铁靴只付 310（710−400）。

### 图标
34 件新装备没有手绘 SVG（一件 20~40 行，画不起）。`34-ui-2.js` 加 `tHx` 别名表，
指到同类旧图标、只换配色。要正式图标就补进 `tH`。

### 回归测试
`herocheck --shop`：买两小件 → 合成中件只付差价 → 出售返 60% → 鞋子合成。
金币有被动收入，所以断言只看"这一步扣了多少"并留 ±15 容差。

## herocheck 的几个脆弱点（已修）
- 滚轮只持续 ~1.2s **模拟时间**，无头里模拟跑得比真机快好几倍，两次 CDP 往返之间就收尾了。
  → 方向采样改到**页面内按帧记**（`__hcRoll` 记最大偏转角），外部只读结果。
- 大招落点常在墙角，后面一路往 +x 推十几米就顶墙 → 先找一条最长的 +x 走廊落位；
  **档位是按实际位移算的，瞬移会清零速度估计**，所以每轮只在开头落位一次。
- 英雄会被塔打死 → 挂 `untargetable` + 每 150ms 回满血。
- `clip` 只有 GLB 模型才有，原生程序化英雄做这些断言没意义 → 跳过而不是判失败。

## 主动装备（金身/传送/回春/净化）
- **主动要计价，被动不计价**：被动是买大件的理由；主动等于白送一个技能，不折成金币的话
  主动件会比同价装备强一大截。`active.value` 进 `statValue()`。
- 冷却挂在**装备栏下标**上（`unit.rt.itemCd[6]`），不挂装备 id：卖掉再买是新的一格，
  换装流不能靠卖-买刷新主动。买/卖装备时对应格清 0。
- 触发两条路：数字键 1~6（`37-ui-5.js` 的 `itemActive(ix)`，带鼠标地面投影给传送用）
  和点状态栏装备格。**Ctrl+1~4 是表情，必须先 return 掉**，否则数字键分支抢走。
- 金身**被控也能按**（那正是它的用途），别的主动被控按不出来 —— 这条顺序在
  `useItemActive()` 里，别把 `act.kind !== "stasis"` 的判断删了。
- 传送直接复用 `recall` buff 的引导（同一套"一行动就中断"的检查点），只换 `onExpire`。
- 视觉不另造美术：金身/净化用 `buff_gain`（脚下金色法阵）、传送用 `recall_start`(落点)
  + 到达的 `recall_done`、回春用 `heal`。`$D` 里没有的 fx 键是**静默跳过**，不会报错，
  所以"新特效键没画面"很好排查。

### 踩过的坑
- **`rH`（状态图标表）漏登记会把整个 HUD 状态行炸掉**：`lH(n){return rH[n]()}`，
  金身一挂上去就 `rH[id] is not a function`。`T3`（状态名）漏了是另一个崩法。
  两处都要登记；`lH()` 现在有兜底，但兜底只是不崩，图标还是错的。
- **"这一步花了多少金币"必须在同一次 eval 里前后夹住**：`world.command` 是同步的，
  跨 eval 取差值会把被动收入（补兵/时间收益）算进来，实测能差 22 金币，
  ±15 容差根本不够。改成 `g0=u.gold; command(); paid=g0-u.gold`。
- 传送要引导 2.5 秒，实战里被控就断，一次断言必然 flaky。给三次机会，有一次到底就算过。
- 金身持续 2 秒、期间算"被控"，紧接着测传送一定按不出来 —— 测试之间要等 2.3 秒。

### HUD 落点

## 装备图标去黑描边 + 提质感
- **`Pe()` 就是黑描边**（`stroke="#070b16"`，全局原语），tH 里用了 41 处；另有 13 处直接写死 `${xe}`。
  全部换成 `eP(n, w)` = 本色压暗 55% 的细软边（宽度再乘 0.8）。孔洞别填纯黑，改半透明深色，
  否则特写下是四个黑洞。**Pe 本身没改**（别的图标可能还在用），只把装备这边的调用换掉。
- **不立体的根因是渐变方向**：竖直物件原来用"左上→右下"的斜渐变 = 上亮下暗，
  看着像一块渐变板。改成垂直于轴线（同 y）才是圆柱受光：左亮 → 高光 → 暗 → 更暗。
  金属把高光收窄（0.18 就压到本色）、暗部拉到 0.74。
- **viewBox 从 `0 0 64 64` 收到 `4 4 56 56`**：内容都在 8~58 之间，放大 14% 不切边，
  68px 的商店格子里终于不显得空。Kh() 加了第 4 个参数 `vb`，默认行为不变。
- **发光圆必须留在投影外面**：`<g filter=feDropShadow>` 包住整段 body 时，
  `We('gw')` 那团柔光会被再糊一次，特写里是一圈脏雾。dn() 里用正则把
  `<circle ... url(#@gw) .../>` 抠出来单独画，主体再进 filter。
- 渐变里 `@` 前缀会被 `Kh()` 换成每个 svg 独有的前缀，所以跨图标撞 id 不用管；
  但**同一个 svg 内部**撞 id 会静默取先出现的那个（dn 自带 `gl`，自定义发光层当初用 `gl` 就吃过这个亏）。
- **批量改 SVG 属性的正则一定要连外层括号一起匹配**：只匹配 `[[0,...],[0.5,n],[1,...]]` 的内层，
  会把外层的 `[` 吃掉、留下一个 `]`，运行时变成 `stops = [0, Hn(...)]` → `number 0 is not iterable`，
  整个选将页起不来。改完必须跑一次页面看有没有异常，不能只看 build 成功。
- 商店格子只有 68px，缩略图看不出描边/高光 —— herocheck 加了 `shop-attack-zoom`（5 倍特写），
  验图标质感只能看这张。

## 图标去重：形制带变体号
- 光"按形制分族"不够：一页商店会排出三根一样的棍子、三个一样的罐子，用户当场骂重复。
  改成 `tHx` 的值可以是 `['blunt', 3]`，`Po()` 把第二项当变体号传给形制函数 `(n, v = 0)`。
- 现在 63 件：棍棒 7 变体 / 瓶装 9 / 罐筒 8 / 盒子 6 / 布被 5 / 外套 2 / 盾门盆 3 /
  喇叭 4 / 面罩 2 / 块状 2，其余 10 件各是一个独立形制。**同一页 9 格内没有重复**。
- 变体的差异要落在"一眼能看出的特征"上：长度、粗细、有没有把手/提手/天线/喷头/盖子、
  分几节、末端是钩还是锤头。只改颜色或尺寸是没用的（缩略图只有 40px）。
- 写变体时把公共件抽成局部函数（`rod(x1,y1,x2,y2,w)` 画一根带软边的杆），
  分支里只写"这根杆 + 什么末端零件"，比每个变体从头画省一半代码。
- 批量替换 tH 里的函数体：用 `### name` 分隔的纯文本文件 + 脚本按 `\n  name: (n` 定位，
  往前找 `\n\n` 当段落起点、往后找下一个形制当终点。**纯文本文件而不是 .mjs**，
  因为函数体里全是 `${}`，写进模板字符串会被提前求值。

## 装备信息卡重做 + 全库文案去模糊化

用户原话：「装备卡太丑了，以后在游戏里写清楚，严禁各种模糊表达，只需要简洁严谨的游戏术语说明」
「babao 里面的小图标可以直接套用」。

**做了什么**

1. 小图标：`src/48-item-icons.js` 从 BaBao 的 `ItemTraitIcons.tsx` 机械搬 20 个 16×16 SVG，
   `traitIcon(key)` 取图。`ek()` 输出补 `key` 字段，详情面板按 key 取图标。
2. **删掉全部 63 件装备的 `brief` 字段**（`tools/itemdesign.mjs` 里已无此字段，
   `ln` 里也没有）。商店卡片副标题改成 `Z4 = (n) => BB(n.stats, 2)` 从 stats 精确生成 ——
   文案和数值从此不可能脱节。这是治"一点点暴击率"这类模糊表达的根本办法。
3. 详情卡重构成"分区小面板 + 极小型标签"：属性 / 被动 / 主动 / 合成路径，
   每块 `.sf-hud__dt-sec` 自带圆角边框和类型色（属性中性、合成蓝、被动琥珀、主动青）。
   顺序按 LoL 惯例：属性 → 效果 → 合成（先知道它干什么，再看它由什么拼成）。
4. 31 条英雄技能 brief 全部改写成"触发条件 + 效果 + 关键数值"，数值逐条取自 `values`。
   例：「5 秒内命中同一目标 3 次：额外法术伤害 + 眩晕 0.75 秒」。
   另修 3 处 tips/desc 里的「一大片」「四成」「一小段」。
5. 面板高度 540u → 600u（不然主动说明被折叠线切掉）；详情列 268u → 292u；
   属性行从两列改**单列**（两列时「冷却缩减」「护盾效率」会被省略号截断）；
   卡片图标槽 60u → 76u；`herocheck` 加 `shotPanel()` 按运行时包围盒裁图（写死坐标一改结构就框偏）。

**踩到的坑**

- 面板窄（292u）时属性行**必须单列**，两列一定截断中文术语。
- 详情面板高度不够时，主动/被动说明会被 `.sf-scroll` 折在下面 —— 加高面板比压缩内容有效。
- 加高商店面板会让装备卡被 grid 的 `1fr` 拉高、中部出现死空；
  `.sf-hud__card-top { margin-top: auto }` 能让图标文字组居中一些。
- `herocheck` 的「停下来的瞬间播急停」仍是 flaky（已知，与改动无关）。

**磁盘**：C 盘跑满了（0 可用），`.workbuddy-ai` 占 9GB（workspace 2.84 / projects 1.68 /
logs 0.65 / traces 0.55 / blobs 0.79）。Grep 工具写临时文件会 ENOSPC。已告知用户待处理。

## 新增消耗品装备（群勃龙 / 康力龙 / 香烟 / 槟榔干 / 发酵果汁）

用户：「新加消耗品装备，比如群勃龙，康力龙，香烟，槟榔干，发酵果汁」。

**设计**：都是"市井提神补身体"的东西，各带一点代价或副作用，贴合主题。
群勃龙（类固醇）扎一针掉 10% 当前血换物攻 +25 / 攻速 +15%；康力龙护甲 +45 且每秒回血；
香烟回蓝 30% 但移速 −8%；槟榔干回血 20% 且移速 +12%；发酵果汁双回血蓝。

**工程**：没有为任何一件写专属分支，全部靠三个原子操作（立刻回复 / 立刻代价 / buffs 数组）。
引擎侧只加了一个 `case 'consume'`。

**踩到的坑（值得记住）**：
1. **空对象序列化成 `{\n,\n}` 是语法错误**。`itemdesign.mjs` 的 `lit()` 对空 `parts`
   必须直接返回 `{}`。消耗品 `stats: {}` 正好撞上。
2. **新 buff id 只加 `_o()` 的 case 不够**，还要登记 `34-ui-2.js` 的 `T3` 和 `rH`。
   漏了 `T3` → HUD 状态行读 `T3[id].kind` 抛 `Cannot read properties of undefined (reading 'kind')`，
   而且这个错**没有堆栈**（`window.onerror` 拿不到 `e.error`），排查绕了很久：
   先给 `case 'consume'` 插 try/catch 发现异常不在那里，才想到是渲染侧。
3. **装备栏有两套渲染**：商店面板 6 格（`X.innerHTML`）和 HUD 状态栏 `Q()`（`Z.el.innerHTML`）。
   只改一处会导致"商店里看得到数量、战斗中看不到"。
4. `rH` 的图标只能用 `M4()` 认的 24×24 符号键。我先传了 `traitIcon()` 返回的完整 `<svg>`，
   那是嵌进 `<g transform>` 里的，尺寸会乱。

**断言**：`herocheck <hero> --shop` 新增 3 项（连买叠格 / 用掉减一且 buff 生效 / 用完清格），
共 36 项。截图新增 `shop-consumable`、`shop-consumable-detail`、`shop-consume-badge`。

**另一个卡了很久的坑：Windows 覆盖写 EPERM**。
`dist/index.html` 和 `.herocheck/*.jpg` 被 WorkBuddy 预览面板打开后，
`fs.writeFileSync` / `fs.copyFileSync` 全部报 `EPERM: operation not permitted`，
但 `fs.unlinkSync` 能成功。一度以为是磁盘满（C 盘确实 0 可用）或杀软，
最后靠"删除能成功、写入不能"这个差异定位到共享读句柄。
`tools/build.mjs` 和 `herocheck` 的 `shot()` 都改成**先删后写**了。
