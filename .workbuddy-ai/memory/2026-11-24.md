## 杯杯菇（mushroom）蒙皮撕裂 + 侧滚方向 修复

### 撕裂真正的根因（上一次的判断是错的）
- 模型是 **70 个互不相连的碎片**（纸片/低模风格，`tools/dump_parts.mjs` 可查）。
- 撕裂只可能发生在**同一碎片内部**：同一碎块的相邻顶点被分到完全不同的骨骼，碎块被拉开。
- 原版权重把整片左侧身体面板（y 0.26~1.05，含臀部）判给了 `L_Thigh`，跑动时大腿一摆就撕。
- 上一次的"Twist 合并 + 相邻骨骼才允许双骨混合"没用，因为**逐顶点**独立选骨骼对，
  同一碎块里 A 点选 (Thigh,·)、B 点选 (Clavicle,·)，边界直接裂开。

### 修法：`tools/reweight.mjs`（不需要原始 GLB）
1. 按连通块分片，统计每片原版权重的骨骼票数 → 判定"族"（head/armL/armR/legL/legR/torso）。
2. 每片**只允许本族相关骨骼**参与（菌盖片绝不会被手臂骨抢走）。
3. 权重 = `1/(到骨骼线段距离)^2`，取前二归一化。
   **纯几何权重是位置的连续函数 → 同一碎块内不可能出现突变 → 结构上不可能撕裂。**
- 结果：Head 1693（菌盖刚性）/ Pelvis 202（身体）/ 大腿只剩 108、36。
- 脚本**只能跑一次**（族判定依赖当前 skin），重跑前先 git checkout 网格模块。

### 侧滚方向
- 错的表现：`R.add(rootJ, 90, angle, 0)` = 先 Rx(90) 把身体前倾放倒，再绕自身头脚轴自转
  → 头顶朝前进方向、像钻头钻地。
- 正确做法：只留 `R.add(rootJ, 0, angle, 0)`（绕模型 Y 轴）。
  `bindQ[root] = Rx(-90°)`，模型 -Y → 世界 +Z，所以**绕模型 Y 转 = 绕前进轴转**，
  肚子朝向恒定朝前，头在竖直平面里划圆 = 侧手翻。旋转中心抬到 y≈0.65 绕身体中部转。
- 通用结论：要让某个朝向在旋转中保持不变，就绕那条法线轴转。

### 工具
- `tools/reweight.mjs` 重算权重（改 `src/45-mushroom-mesh.js` 的 skin 字段）
- `tools/dump_parts.mjs` 连通块 + 每片主导骨骼，查"哪块被谁吃了"很快
- `tools/skincheck.mjs` 离线撕裂检测（自检误差 0.025，模型尺度 2.0）
- `tools/glb2hero.mjs` 已同步成同一套算法（按碎片分族 + 几何权重），
  重新用 GLB 生成不会再带回撕裂；旧的 boneAdj/twistToMain 逻辑已删除。
- `tools/_toyglb.mjs` 生成最小蒙皮 GLB，仓库里没有原始 GLB 时用它冒烟验证导入管线。
