# 装备系统与定价模型

63 件装备（含 4 双鞋），三档：**小件 150–720 / 中件 880–1350 / 大件 1630–3430**。
中件由 2 件小件合成，大件由 2 件中件合成；凑齐组件再买成品，只付差价。

**主题是"现代市井"，不是西幻。** 没有刀剑弓甲，只有警棍、钢管、扳手、大铁锤、板砖、
防暴盾牌、敌敌畏、杀虫喷雾、充电宝、饭盒、奶粉罐、十斤大棉被、电动车、不锈钢大盆……
装备皮要让人一眼看出"这是从楼下杂物间抄出来的"。改名时 id 也一起换掉了
（`iron_sword → baton`、`azure_blade → police_baton`），英雄出装表已同步。

## 一、定价模型

不凭手感标价。把每个属性折算成"等效生命(EHP)"或"等效普攻 DPS"，在**同一个参考站桩点**上比较，
再统一换算成金币。参考点取 **等级 10、0 装备的平均英雄**（7 个英雄取平均）：

```
生命 6009   护甲 276   魔抗 128   物攻 262   攻速 1.00   暴击伤害 2.0
```

公式全部来自引擎 `src/43-data-3.js`，不是另编一套：

| 机制 | 引擎实现 |
| --- | --- |
| 物理/法术减伤 | `dmg × 600/(600+护甲)` |
| 攻速 | `基础攻速 × (1 + 攻速加成)`，上限 2.5 |
| 暴击 | `伤害 × 暴击伤害`（基础 2.0） |
| 冷却缩减 | `cdMax = 冷却 × (1 − CDR)`，上限 40% |
| 穿透 | `护甲 × (1 − 穿透)`，上限 80% |
| 法强 | `(基础 + 法强) × (1 + 法强%)` |

在这个站桩点上，每点属性的边际收益是：

```
1 生命  = 1.46 EHP
1 护甲  = 10.0 EHP   → 与生命等价价 6.86 金
1 物攻  = 0.685 DPS
1% 攻速 = 1.795 DPS
1% 暴击 = 1.795 DPS
1% 穿透 = 0.565 DPS
```

### 单价表（金币 / 1 点）

| 属性 | 单价 | 说明 |
| --- | --- | --- |
| 生命 | 1.0 | **锚点**，1 生命 = 1 金币 |
| 护甲 | 4.2 | EHP 折算值 6.86 打 6 折：护甲只挡物理，实际覆盖面约六成 |
| 魔抗 | 3.9 | 同上，比护甲再便宜一点（法师位少） |
| 物攻 | 15 | 锚点 |
| 法强 | 9 | 0.6 × 物攻 |
| 法力 | 0.5 | |
| 攻速 | 1600 / 1.0 | 每 1% = 16 金 |
| 暴击率 | 1600 / 1.0 | 每 1% = 16 金 |
| 暴击伤害 | 1200 / 1.0 | 没有暴击率时几乎不产生价值，所以打折 |
| 吸血 | 3000 / 1.0 | |
| 护甲穿透 / 法术穿透 | 1600 / 1.0 | 同上，单独存在时是废属性 |
| 冷却缩减 | 2600 / 1.0 | 封顶 40%，越接近上限越不值钱 |
| 法强% | 1800 / 1.0 | |
| 移速 | 500 / 1.0 | 草鞋锚点（250 金 = 0.5 移速） |
| 回血 | 8 / 每秒 | 英雄基础 7–12/秒，按 3 金算等于白送续航 |
| 回蓝 | 6 / 每秒 | 英雄基础 3–4.2/秒 |
| 生命→物攻 | 90135 / 1.0 | 即 1% ≈ 901 金（参考点 6009 血 × 15 金/物攻） |
| 护盾效率 | 900 / 1.0 | 25% ≈ 225 金；只在有护盾来源时才产生价值 |
| 治疗加成 | 700 / 1.0 | 40% ≈ 280 金；同上，没治疗就是废属性 |

### 目标效率

```
小件  100%   组件不亏不赚，否则玩家会想办法跳过它们
中件  102%   合成让 2%，鼓励攒件
大件  108%   再白送一件被动，作为"攒够钱"的正反馈
```

装备价值 = Σ(属性 × 单价) + 主动价值 + **中件被动折价**。

- **被动默认不计价**（被动就是买大件的理由）。
- **但中件上的被动必须写 `passive.gold` 显式折价**：中件本身只让 2%，
  再白送一个被动，效率会跌破 96% 被自检拦下（饭盒的"边吃边回"折 500 金、
  野生狗奶的"野生配方"折 1100 金）。`itemValue()` 会把 `passive.gold` 加进去。
- **主动必须计价**（`active.value`），见第四节。

## 二、怎么改

所有装备只在 `tools/itemdesign.mjs` 里定义一次，改完两条命令写回源码：

```bash
node tools/itemdesign.mjs            # 打印三档装备 + 效率，检查有没有越界
node tools/itemdesign.mjs --emit     # 生成 tools/_ln.js
node tools/splice-items.mjs          # 替换 src/33-data-2.js 里的 ln
node tools/build.mjs                 # 打包
```

`node tools/itembalance.mjs` 直接读**线上源码**算效率，改完随时复查。

### 加一件新装备

1. 在 `tools/itemdesign.mjs` 的 `ITEMS` 里加一条，`tier` 决定定价档位，`from` 写合成路径（可省）。
2. 不给 `cost` 就按模型自动定价；给了 `cost` 就按你给的价格算效率，越界会报错。
3. **新装备必须有图标**：`src/34-ui-2.js` 的 `tH` 里是手绘 SVG 形制（26 个），
   `tHx` 是"63 件 → 26 个形制"的映射。加装备时先在 `tHx` 里归到最像的形制上
   （棍棒 / 瓶装 / 罐筒 / 块状 / 布被 / 外套 / 铁丝网 / 盾门盆 / 喇叭 / 盒子 /
   头盔 / 面罩 / 马甲 / 车 / 指虎 / 钢钉 / 弹弓 / 铁链 / 扳手 / 锤 / 哑铃 / 射钉枪），
   颜色自动跟着装备自己的 `color` 走；真看不下去再在 `tH` 里加同名键单独画。
4. 想进推荐出装，再改 `src/02-data.js` 里对应英雄的 `build` 数组。

### 被动的限制

被动 id 在 `src/44-data-4.js` 的 `ql()` 里注册，一共 8 个：
`execute_bonus` `onhit_magic` `spell_slow` `cripple_aura` `spell_shield` `regen_ooc` `thorns` `mana_battery`。
`rS()` 会**按被动 id 去重**——同一个被动的两件装备只生效一次。所以新装备要么复用已有 id，要么无被动。

`mana_battery` 是本轮新加的，走的是新钩子 `onManaSpent`：

```
onDamageTaken(受击, 伤害值)  → 法力 += 伤害 × value      （饭盒 15% / 野生狗奶 25%）
onManaSpent(耗蓝)            → 治疗自己 耗蓝 × value2   （饭盒 20% / 野生狗奶 35%）
```

`onManaSpent` 挂在**全游戏唯一的扣蓝点**上（`src/43-data-3.js` 的 `t.mana -= a.cost`，
约 1943 行），扣完立刻分发，所以"技能真的扣了蓝"才会回血，蓝量不足施法失败不会回。

## 三、合成怎么算

`src/43-data-3.js` 的 `cS()`：

1. `Sk(unit, id)` 先看背包里有没有 `from` 列出的**全部**组件；
2. 凑齐 → 吃掉这些格子，只扣 `cost − 组件总价`，成品放进第一个空出来的格子；
3. 没凑齐 → 走老路（鞋子按 70% 折价替换，其余找空格付全价）。

`Gf()` / `zm()` 同步改了，所以商店卡片上的价格、`还差 X 金币`、自动出装的购买时机
都会自动按"差价"算，不需要另写一套。

回归测试挂在 herocheck 上：

```bash
node tools/herocheck.mjs panyue --shop        # 买小件 → 合成中件 → 出售 → 鞋子合成 → 三件主动
node tools/herocheck.mjs panyue --shop --shots  # 顺带截商店界面 / 装备格冷却
```

## 四、主动装备

**主动要计价，被动不计价。** 被动只是属性之外的赠品；主动等于白送一个技能，
所以 `active.value` 会加进 `statValue()`，否则主动件会比同价装备强一大截。

现有 4 件带主动，都在辅助分类（`category: "support"`）：

| 装备 | 主动 | 效果 | CD |
| --- | --- | --- | --- |
| 不锈钢大盆 | 扣盆 | 2 秒不可选中 + 免疫伤害，也不能行动（`stasis` 状态） | 75s |
| 电动车 | 骑走 | 引导 2.5 秒后骑到 30 米内的指定落点 | 90s |
| 大锅菜 | 开饭 | 治疗周围 8 米友军 220 + 施法者 6% 最大生命 | 60s |
| 藿香正气水 | 灌一瓶 | 解除自身所有控制，1.5 秒内免疫控制 | 70s |

### 冷却挂在"格子"上，不挂在装备 id 上

`unit.rt.itemCd[6]` 是装备栏六个下标各自的冷却。卖掉再买回来是新的一格，
冷却跟着格子走（换装流不能靠卖-买刷新主动）。买/卖装备时对应格清 0。

### 触发链路

```
数字键 1~6 ──┐
             ├→ { type: "item", index, pos } → Aj() → useItemActive()
点装备格 ────┘
```

- `src/37-ui-5.js` 的 `itemActive(ix)`：把鼠标在场景里的地面投影一起带上（传送要用），
  拿不到就传 `null`，由引擎退化成"朝正前方飞满射程"。
  **Ctrl+1~4 是表情，必须先于数字键分支 return 掉。**
- `src/43-data-3.js` 的 `useItemActive()` 按 `ln[id].active.kind` 分派：
  `stasis` / `teleport` / `heal` / `cleanse`。
  - 扣盆**被控也能按**（那正是它的用途）；别的主动被控按不出来。
  - 骑走复用 `recall` buff 的引导，同一套"一行动就中断"的逻辑，只换 `onExpire`。
- 视觉不另造美术：扣盆/灌一瓶用 `buff_gain`（脚下金色法阵），骑走用 `recall_start`
  （落点蓝色光环）+ 到达时的 `recall_done`，开饭用 `heal`。

### HUD 上要看得到

- **状态栏装备格**（`src/40-ui-8.js` 的 `Q()`）：带主动的格子加 `is-act`（青色描边）、
  右下角标数字键、冷却时盖一层 `conic-gradient` 扇形 + 中间读秒。
  `--t` = 剩余比例，1 全黑、0 消失。
- **商店详情面板**（同文件 `qt()`）：被动是琥珀块，主动是青色块，标题右侧挂冷却秒数。
- 触摸端点装备格就能放（落点交给引擎兜底）。

### 加一件带主动的装备

1. `tools/itemdesign.mjs` 里写 `active: { name, desc, cd, kind, ...参数, value }`，
   `value` 是这件主动折算的金币（会加进总价值）。
2. `kind` 必须是 `useItemActive()` 里已有的四种之一，否则会走到 `default` 报"没有主动"。
3. 新 `kind` 要自己补 `switch` 分支 + 状态（`src/43-data-3.js` 的 `Vf()`）、
   状态名（`src/34-ui-2.js` 的 `T3`）、状态图标（同文件 `rH`，漏了会 `rH[id] is not a function`——
   `lH()` 现在有兜底，但还是要登记）。
4. 冷却 / 数值改完记得重跑 `node tools/itemdesign.mjs` 看效率有没有越界。

## 五、蓝量 / 血量联动 / 辅助加成

### 法力件

| 装备 | 档 | 属性 | 备注 |
| --- | --- | --- | --- |
| 充电宝 | 小 160 | 法力 320 | 最纯的撑蓝件 |
| 奶粉罐 | 小 330 | 法力 260 + 生命 200 | 饭盒之外的第二个组件 |
| 饭盒 | 中 980 | 法力 400 + 生命 300 | **被动 边吃边回**：受伤 15% → 法力，耗蓝 20% → 生命 |
| 野生狗奶 | 大 2510 | 法力 900 + 生命 900 + 冷却 10% | **被动 野生配方**：25% / 35%，量翻倍 |

饭盒 = 充电宝 + 沙发垫；野生狗奶 = 饭盒 + 奶粉罐。**饭盒不是野狗奶的组件之一就说不通**，
所以奶粉罐专门为这条链做了一件小件（原来它只服务法系）。

### 血量联动

| 装备 | 档 | 属性 | 备注 |
| --- | --- | --- | --- |
| 哑铃 | 中 1350 | 生命 300 + 生命→物攻 1.2% | 按**最大生命**百分比加物攻 |

`hpToAdPct` 在 `_o()` 里是**先算 maxHp 再算 ad**：

```js
(r.ad = (o.ad + pe.ad + r.maxHp * pe.hpToAdPct) * (1 + pe.adPct))
```

顺序不能反——先算 ad 的话 `r.maxHp` 还是上一帧的旧值，换装/升级那一帧会少一截。
参考点 6009 血时 1.2% = 72 物攻；堆到 3700 血的大件加满，哑铃能给出 100+ 物攻，
所以它贵在中件档的上限（1350）。

### 护盾效率 / 治疗加成

| 装备 | 档 | 属性 | 备注 |
| --- | --- | --- | --- |
| 急救箱 | 中 1030 | 生命 700 + 护盾效率 25% + 冷却 5% | 便宜的中件，给软辅 |
| 消防栓 | 大 2310 | 生命 1200 + 护甲 200 + 护盾效率 50% | 防暴盾牌 + 防盗门 |
| 红糖姜茶 | 大 2270 | 法强 130 + 生命 1000 + 治疗加成 40% | 保温壶 + 沙发垫 |

两条链路都不改调用方，只在出口处放大：

- **护盾**：`Wn(n, t, "shield", { value })` 是所有护盾的必经之路
  （技能护盾、被动保命盾、装备护盾三条路都汇到这里）。开头按**施加者**的
  `stats.shieldPower` 放大：优先取 `s.sourceId` 指向的单位，没有就取受盾者自己。
- **治疗**：`xS()` 是所有持续治疗的出口，按**施法者**的 `stats.healPower` 放大；
  装备主动 `heal` 分支（大锅菜）另外乘一次 `1 + healPower`。

**注意 `?? 0`**：小兵和塔的 `base` 里没有这两个字段，写成 `(o.shieldPower)` 会
`undefined + 0 = NaN`，整条属性链全变 NaN。

## 信息卡与文案规范

装备信息卡（商店右侧详情）和技能提示**只写能算的东西**。三条硬规则：

1. **属性一律"术语 + 数值"**：写「冷却缩减 +5%」，不写「一点点冷却缩减」。
   属性名只能取自 `33-data-2.js` 的 `tk` 表，数值由 `ek()` 生成，不手写。
2. **不写 brief 这类一句话概括**。63 件装备的 `brief` 字段已整体删除
   （`tools/itemdesign.mjs` 里没有这个字段，`ln` 里也不会有）。
   商店卡片副标题改由 `Z4 = (n) => BB(n.stats, 2)` 从 `stats` 精确生成，
   这样文案永远不会和数值脱节。
3. **技能 brief 只写"触发条件 + 效果 + 关键数值"**，数值必须来自该技能的 `values`。
   例：「5 秒内命中同一目标 3 次：额外法术伤害 + 眩晕 0.75 秒」，
   而不是「技能打中同一人三次就眩晕」。

### 小图标

`src/48-item-icons.js` 是从 BaBao（`G:/github/BaBao/src/components/ui-svgs/ItemTraitIcons.tsx`）
直接搬过来的 16×16 属性矢量，20 个 key。`traitIcon(key)` 取图，未知 key 回落到灰点。
key 由 `ek()` 带出（`{ key, label, value }`），所以新增属性只要在 `TI` 里补一条。

### 详情卡结构

`40-ui-8.js` 的 `qt()`：属性 → 被动 → 主动 → 合成路径，每块是一个独立圆角小面板
（`.sf-hud__dt-sec`）配一行极小的分区标签（`.sf-dt-label`）。空块不渲染，
不写「无被动」——缺席就是默认。合成路径排在效果之后：先知道它干什么，再看它由什么拼成。
