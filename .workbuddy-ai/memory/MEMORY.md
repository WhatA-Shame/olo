# 项目长期笔记

## 项目
星陨战纪 Starfall v0.1 —— 从线上单文件构建恢复的网页 5v5 MOBA（Three.js + WebAudio，全程序化美术音效）。
仓库：`G:/github/olo`。结构见 README：`src/`（44 个 ES 模块，可编辑）、`modular/`（开发入口）、`dist/`（构建产物）、`_recover/`（原始 bundle + 格式化单文件）、`tools/`（analyze/split/scc/build）。

## 用户偏好
- **后台任务要静音且尽量少占用**：需要看渲染结果时用一次性 `chrome --headless --screenshot`，不要开长驻 CDP 会话；浏览器实例一律加 `--mute-audio`；本地服务器只在验证期间起，用完立刻停，不挂着；长时间任务先说明耗时和资源占用再跑。
- 中文交流。
- **别为了验证一个已经能看到的结论反复跑离线分析**：直接出截图看，比推导数值快得多也省额度。用户对额度消耗敏感，长循环先停手问一句。
- **Windows 上"覆盖写"会被预览面板锁死（EPERM）**：`dist/index.html` 和 `.herocheck/*.jpg`
  一旦被 WorkBuddy 预览面板以共享读方式打开，`writeFileSync` / `copyFileSync` 直接
  `EPERM: operation not permitted`，但 `unlinkSync` 是允许的。`tools/build.mjs` 和
  `herocheck` 的 `shot()` 都已改成**先删后写**。以后再遇到 EPERM 先想到这个，别去查磁盘/杀软。

## 关键经验：外部骨架蒙皮
- 杯杯菇的 GLB 是 **70 个互不相连的碎片**，撕裂只发生在同一碎片内部 —— 同一碎块的顶点被分到不同骨骼就会裂。
  **逐顶点**独立选骨骼对是错的；必须让"碎块内权重是位置的连续函数"（纯几何权重天然满足）。
- 权重做法：按连通块判定骨骼族 → 每块只允许本族骨骼 → `1/距离²` 取前二。见 `tools/reweight.mjs`。
- `bindQ[root] = Rx(-90°)`（模型 Z 轴朝上）。**要让某个朝向在旋转中不变，就绕那条法线轴转。**
- 侧滚最终定案（用户确认）＝**放平横躺侧滚**：`add(rootJ,0,90,0)` 把身体放平成水平（头转成朝侧向、肚子仍朝前），
  再 `add(rootJ,0,0,ang)` 绕头脚轴整圈滚；`move(rootJ,-1.04,1.02,0)` 让身体居中、最低点贴地。
  `r_max=1.023`、身体沿轴质心 `1.038` 由 `tools/_rollsize` 类脚本量的。
  走过的弯路：①`Rx(90)`+绕头脚轴自转 = 头顶朝前钻地；②绕前进轴侧手翻 = 肚子朝前但会浮空/像转硬币。

## 关键经验：外部 GLB 的贴图（"白模"就出在这）
- **占位图必须和真实贴图同尺寸。** three 的 `texStorage2D` 是不可变存储：第一次上传按占位图尺寸分配，
  之后换 `tex.image` 只走 `texSubImage2D`，尺寸对不上整张被丢弃 → 永远显示占位色。
  1×1 占位 + 512×512 真图 = 经典白模。生成器把真实宽高读出来写成 `TEX_W/TEX_H`。
- **网格模块必须在加载时预热解码**：`setTimeout(() => heroMap(), 0)`。少了它，选将台会在解码完成前
  把立绘渲染进 `j1` 缓存并永久保留。新增英雄时 `32-ui.js` 的 `MAP_HEROES` 也要登记。
- 排查：运行时把 `uMapOn` 置 0 —— 画面变纯白说明贴图本来就在正常工作；不变说明没生效。
  `gl.getUniformLocation(prog,'x') === null` 表示该 uniform 被优化掉（源码里没用到），
  能立刻区分"值不对"和"源码不是我以为的那份"。
- `herocheck` 有两条静态断言守这个（预热行 + 占位尺寸），别删。


## 关键经验：把手持武器挂到外部骨架上（"柄方向怎么摆都不对"就出在这）
- Tripo 骨架的手骨局部轴：**X = 掌背→掌心、Y = 腕→指尖、Z = 拇指→小指**。
  拳头是**沿局部 Z 的握孔**（手指卷起来抱住的那根轴）。
- 所以武器柄轴必须写 **+Z**，并且顶点整块写在**手骨局部坐标**里（外面套 `t.g(handMatrix(...))`）。
  按世界坐标摆"竖直的柄"必然错：世界 +Y 换算到局部是 `(0.44,-0.90,0)`，和手指只差 26°，
  看着像一根竖直杆粘在手上，而不是被手握住。牛伟的斧头为此被骂了三四次。
- 待机想让柄竖起来，再给手腕加 `HAND_ROLL = 90`（绕手骨 X 轴翻），把握孔从朝前转成朝上。
  动画状态里 `play()` 会覆盖腕部四元数，那个 roll 加不进去也不该加。
- 单骨 `weight=1` 刚性蒙皮 = 任何姿势下都攥在手里，不会脱手。
- **查朝向/角度优先用离线 FK 算**（读 `bindWQ` + 片段关键帧，几秒出结果），
  别为了看一眼方向去开无头浏览器截图 —— 后者贵一个数量级。
- `herocheck --crop=x,y,w,h,scale`：战场相机固定俯视，英雄大致钉在屏幕 `(350,170)`，
  用这个抓手部特写。

## 关键经验：程序化动作（外部骨架没片段时怎么摆）
- 外部 Tripo 骨架只带 5 段片段（run/box_03/chop/dance_05/defeat_03）。`chop` 实测是**水平横扫**
  （斧尖前后扫 1.8m、柄接近水平），`dance_05` 是跳舞 —— 举过头顶的劈砍、旋身、咏唱都没有现成的。
  程序化动作放 `src/26-pose.js`：`chopPose` / `spinPose` / `chantPose`，纯旋转叠加。
- 手臂三根骨的局部轴：**Z≈世界正前、Y=沿骨骼、X=竖直平面内垂直**。
  绕 X = 前下方抡、绕 Z = 侧向抬（armsDown 用它）、手的局部 Z = 握孔。
  根骨骼局部 **Z = 世界竖直**，`pre(root,0,ang,0)` 就是绕竖直轴转。
- **手腕角度要反解不要手调**：柄与竖直夹角 ≈ `tilt0 - (上臂X+前臂X+手腕X)`。
- **离线摆动作**：`tools/_posetest.mjs`（chop/spin/chant/axes/solve），改一个角度重跑一秒出结果，
  比开无头浏览器快一个数量级。**注意欧拉顺序必须是 Rx·Ry·Rz（three 的 'XYZ'）**，
  我按 Rz·Ry·Rx 算过一次，直接得出了完全相反的结论。
- 选将台预览调试：`?anim=X&p=0.5&passive=1`（`herocheck --anim= --q= --selectonly`）。
  一次性动作的时长以前一直是 0，所以 `?anim=` 从来没生效过，现在能冻结在指定进度截图。

## 关键经验：原版角色皮（卡丁车那 20 个模型）
- **"随便套个简单的皮"= 用素材里已有的模型，不是我画一个。** 手写程序化人形皮被用户当场否掉。
- 管线一条命令：`node tools/kartbuild.mjs`（打包 `.kart/entry.js` → 无头 Chrome 调 `glbExporter` 导 GLB
  → `tools/glb2kart.mjs` 转 `dist/kart/<id>.bin`）。运行时 `preloadKart(id)` fetch + `registerModel()`。
- 这批是**节点动画**为主：节点层级直接当骨架，顶点权重 1 绑自己那根骨。
- **但有 7 个模型的"身体"是真蒙皮网格**（大肥蛆/杯杯菇/大脚牛/小肥石/雪松老师/半马人/椰子保龄球）。
  三件事必须同时成立，身体才会蠕动（少一条就"只有脑袋在动"或"被拉断"）：
  ① 引擎支持**四骨**混合（`aSkin` + `aSkin2`，骨B 权重按 `1−wA−wC−wD` 反推；`aSkin2` 必须无条件设在每个几何上，
     缺属性会拿到 WebGL 默认 `(0,0,0,1)` = 骨D 权重 1）；
  ② 绑定姿态取 **`inverseBindMatrices`**（`meshWorld·inverse(IBM)`），不是节点静置 TRS —— 这几只的绑定姿态是"旋转全归零的直骨"；
  ③ `localTRS()` 的矩阵分支曾经解出**共轭四元数**（反对称项全反号），只有 `n.matrix` 节点走，平时不触发，反解 IBM 正好走它。
- 对基准用 `tools/_glbskin.mjs`（原始 GLB 完整 4 骨矩阵 LBS，`--top2`/`--node=`/`--edge=`/`--bones=`）
  和 `tools/_diag3.mjs`（最差边两端点的四骨权重 + 骨骼世界变换）。**形变问题先对基准，别开无头浏览器截图猜。**
- **骨索引 u16**（多脚纸箱 304 根骨，u8 截断会散架）；**贴图色先 sRGB→线性**再烘进顶点色。
- **`def.height` 是声明身高不是几何高度**：渲染器把 `height*scale*Z` clamp 到 `[3.05,3.55]`，`scale` 被约掉。
  写 `height = 3.05/k`，`k = min(3.15/rawH, 2.8/rawW, 1.6)`。填真实高度会让趴着的蛤蟆横向铺 8 米宽。
- 这批模型自带朝向 **+Z**（蛤蟆舌头 z=+1.48、熊猫摩托前轮 +Z），和引擎 forward 一致；
  选将台相机也在 +Z。**看着像侧身是错觉，别再为此加 yaw 修正。**

## 关键经验：占位皮的动作（"动作都是自己编的"就出在这）
- **卡丁车工程里有 20 段标准动作**（`.kart/src/core/entityShared.ts` 的 `所有标准动作`），
  导出器以前只挑 4 段。现在导 10 段并按状态一一对应：
  idle→待机 move→跑起来 attack→普通攻击 attack2→右攻击 cast_s1→左攻击 cast_s2→右攻击
  ult/channel→吟唱 hit/hurt→眩晕 spin→失控 dead→死亡。**全是原版片段，不叠加任何程序化动作。**
- **先翻源工程的枚举再动手**：默认"原版只有 4 段"就会自己补动作，用户一眼就看出是编的。
- `.bin` 每关节每帧存 **10** 个数（t.xyz + q.xyzw + **三轴缩放**）。**scale 必须存 `anim/rest` 而不是绝对值** ——
  引擎 `sw.s` 是乘在子骨偏移上的系数（静置=1），存绝对值静置姿态就变形。归一化后立绘和以前一模一样。
  量化 i16 ×10000。**缩放不能压成几何平均**：原版挤压是"压扁同时横向变宽"（轴向比中位 1.26、最大 13.3），
  一个标量就把形变抹平了，用户会直接问"你这模型不能形变吗"。
- **缩放要乘在骨骼自己的轴上**：顶点必须先搬到骨骼局部空间（`v_local = R(bindQW)⁻¹·(v_bind − bindWorld)`，
  单骨权重 1 所以精确），`rig.localVerts = true` 走 `pack` 的快路径；否则缩放落在世界轴上，
  斜着放的零件会往错方向压 = "拉断"。骨骼纹理每骨 3 texel，着色器 `ps + qrot(q, position*sc)`、法线按 `S⁻¹`。
- `tools/kartexport.mjs --only=` 比的是模型**中文名**，皮 id 永远比不中、静默导 0 个；
  kartbuild 现在翻成序号传 `--only-index=`。
- **选将台 `?anim=` 传的是状态名，不是片段名**：`dead` / `cast_s1` / `emote_cheer` / `cheer` / `stop` / `move`…
  传 `die` / `attackL` 会静默退回 idle —— 看着像"参数没生效"，其实名字不对。配 `?p=0.45` 冻结进度。
- **"模型光滑水润"= 硬边高光 + 平滑法线 + 没有贴图**：卡丁车走 cloth 类别（`mp.x=0`）→
  `sAmt = vFx.x*uSpec.x = 顶点gloss0.34 × 默认0.9 = 0.31`，且 `mp.x==0` 时 `hard=0.08`（硬边亮斑）。
  已改 `gloss:0` + `def.specular=0`（`?gloss=1` 可 A/B）。更彻底的办法是接回原版贴图：
  颜色现在是每顶点采样一次 UV 烘成顶点色，512×512 的细节全丢了；`TL` 的 `uMap` / `def.map` 通道是现成的。

## 关键经验：顶点动画网格（"零件整块冻在待机姿态"就出在这）
- 卡丁车这批**大部分是节点动画**，但蛤蟆的"连体融合肉套"是**每帧在 CPU 上重建顶点几何**
  （`创建融合肉套网格`，4 条腿各 187 顶点）。这份形变不在节点 TRS 里，GLTFExporter 只导导出那一刻的几何，
  动画里整块被冻住 —— 表现就是"站起来走时腿脚分开"。
- 判据：采样前后对比 `geometry.attributes.position.version`（`needsUpdate` 会 +1）。
  名单随 `.dyn.json` 传给 `tools/glb2kart.mjs`，那边改成真蒙皮（打开 `bindSpace`）。
- 权重**必须整块共用一对骨**（网格两端最近的结构骨 + 沿连线 smoothstep），逐顶点选骨会把网格撕成刀片。
  选骨要排掉两类假骨：① 斑点/贴片（每个小圆点都是独立网格节点），② 位置重合的装饰关节。
- **`_fkcheck --parts` 只能证明"我们忠实复现了 GLB"，证明不了 GLB 忠实于原版。**
  要看原版就 `.kart/shot.js`（`?diff=1` 红绿叠加差分，一眼定案）。
- 临时脚本里 `d.mesh.pos` 是**烘焙后的世界坐标**，必须先 `conj(bindWQ)·(v−bindWorld)` 搬到骨骼局部空间
  （引擎加载时做这一步），漏了会算出 1.8 的假偏差。

## 关键经验：装备系统（63 件 / 三档 / 合成 / 市井主题）
- **主题是"现代市井"，不许出现刀剑弓甲**（用户明确否掉西幻皮）：警棍、钢管、大扳手、板砖、
  防暴盾牌、敌敌畏、杀虫喷雾、充电宝、饭盒、奶粉罐、十斤大棉被、电动车、不锈钢大盆。
  **改名要连 id 一起改**：英雄 `build` 表（`02-data.js`）、`herocheck` 商店断言、`tH` 的鞋子键名
  三处必须同步，漏一处就挂。
- **定价不靠手感**：`tools/itembalance.mjs` 把属性折成 EHP / 等效 DPS，在"等级 10 裸装平均英雄"
  这个站桩点上比（HP 6009 / 甲 276 / 魔抗 128 / 物攻 262 / 攻速 1.0），1 生命 = 1 金币作锚点。
  **护甲/魔抗要在 EHP 折算值上打 6 折**（只挡一类伤害），不打折的话"护甲铁靴"效率 149%，一眼假。
- 目标效率：小件 100% / 中件 102% / 大件 108%。见 `docs/ITEMS.md`。
- **被动默认不计价，但中件上的被动必须写 `passive.gold` 显式折价**：中件只让 2%，
  再白送被动会跌破 96% 被自检拦下。`itemValue()` = 属性 + `active.value` + `passive.gold`。
- 派生属性三条，都在 `_o()` 累加：`hpToAdPct`（哑铃，**先算 maxHp 再算 ad**）、
  `shieldPower`（`Wn()` 出口按施加者放大）、`healPower`（`xS()` + 装备主动 heal 分支）。
  **小兵/塔的 base 没有这两个字段，必须 `?? 0`**，否则 NaN 传染整条属性链。
- 新钩子 `onManaSpent` 挂在唯一扣蓝点 `t.mana -= a.cost` 后面（饭盒/野生狗奶的"耗蓝回血"）。
- **装备只在 `tools/itemdesign.mjs` 里定义一次**：`--emit` → `tools/splice-items.mjs` 写回
  `src/33-data-2.js` 的 `ln`。`ln` 是多变量声明链第一项（`const ln = {...}, IB = ...`），
  收尾是 `}` + 逗号，别拼成 `};`。序列化器要单独判 `Array.isArray`，否则 `from` 会变对象、合成静默失效。
- 合成：`Sk()`（39-ui-7）判断能否合成，`cS()`（43-data-3）吃掉组件只扣差价；`Gf()`/`zm()` 同步改，
  商店价格、"还差 X 金币"、自动出装时机就自动按差价算。
- 图标走"**形制分族**"：`34-ui-2.js` 的 `tH` 是 26 个手绘形制，`tHx` 是"63 件 → 形制"的映射，
  颜色跟装备自己的 `color`。**族分得太粗会排出一列一模一样的图标**（用户一眼看出来），
  所以最常露面的单件要单独画。`dn()` 内部已占用渐变 id `gl`，自定义发光层用 `gw`。
- 回归：`herocheck <hero> --shop [--shots]`。**`--shop` 和 `--shots` 是独立开关**，
  只给 `--shots` 会跳过商店那 8 项断言（23 vs 31 项）。

## 关键经验：主动装备（扣盆/骑走/开饭/灌一瓶）
- **主动要计价，被动不计价**：被动是买大件的理由；主动等于白送一个技能。
- 冷却挂**装备栏下标**（`unit.rt.itemCd[6]`）不挂装备 id —— 换装流不能靠卖-买刷新主动。
- 触发：数字键 1~6（`37-ui-5.js` 的 `itemActive(ix)`，带鼠标地面投影给传送）+ 点状态栏装备格。
  **Ctrl+1~4 是表情，必须先 return 掉。** 扣盆**被控也能按**，别的主动不能。
- 骑走复用 `recall` buff 的引导（同一套"一行动就中断"），只换 `onExpire`。
- 视觉复用现有 fx：`buff_gain`（脚下法阵）/ `recall_start`+`recall_done` / `heal`。
  `$D` 里没有的 fx 键**静默跳过**，所以"新特效键没画面"很好排查。
- **加状态必须同时登记 `T3`（状态名，34-ui-2）和 `rH`（状态图标，同文件）**，
  漏 `rH` 会 `rH[id] is not a function` 把整个 HUD 状态行炸掉；`lH()` 现在有兜底但不解决图标错。
- 测试金币差价：`world.command` 是同步的，**必须在同一次 eval 里 `g0=u.gold; command(); paid=g0-u.gold`**。
  跨 eval 取差值会把被动收入算进来（实测差 22 金币），±15 容差不够用。

## 关键经验：游戏内文案（"严禁模糊表达"是硬规则）
- **不写一句话概括式的 brief**。63 件装备的 `brief` 字段已整体删除，商店卡片副标题由
  `Z4 = (n) => BB(n.stats, 2)` 从 stats 精确生成 —— 文案和数值不可能脱节。
  **别再加回来**：一旦手写摘要，改数值时就会忘记同步。
- 技能 brief 格式固定为「触发条件 + 效果 + 关键数值」，数值必须来自该技能的 `values`。
  禁止「更疼 / 一大片 / 一小段 / 三成 / 残血」这类无法量化的词。
- 属性名只能取自 `33-data-2.js` 的 `tk` 表，数值走 `ek()`，不手写。
- 属性小图标 `src/48-item-icons.js` 搬自 BaBao 的 `ItemTraitIcons.tsx`（20 个 key），
  `traitIcon(key)` 取图；`ek()` 带出 key。

## 关键经验：消耗品（叠加 / 用完清格 / 两处装备格渲染）
- `category:'consumable'` + `stack:N`。数量存 `rt.itemN[格]`（和 `itemCd` 同构）。
- 定价**不进效率带**（没有常驻属性），`cost` 手写；`itemdesign.mjs` 的自检里对
  consumable 单独校验"有 cost、stack>1、有 active"。
- 购买走 `cS()` 最前面的独立分支（必须在合成分支**之前**，消耗品没有 from）。
  出售 `bj()` 按 `cnt` 倍退款并清 `itemN`。
- `useItemActive()` 的 `case 'consume'` 只有三个原子操作：立刻回复（heal/mana/healPct/manaPct）、
  立刻代价（costHpPct，`Math.max(1,...)` 保底）、持续增益（buffs 逐条走 `Wn()`）。
  **新消耗品不需要改引擎**。
- **新 buff id 必须同时登记 `T3` 和 `rH`**（都在 `34-ui-2.js`）。漏 `T3` 会抛
  `Cannot read properties of undefined (reading 'kind')`，整个 HUD 状态行不渲染 —— 我踩过。
  `rH` 的图标只能用 `M4()` 认的 24×24 键（damage/shield/heart/mana），**别塞完整 `<svg>`**，
  `Hs()` 是嵌进 `<g transform>` 里的。
- `hp_regen`/`mana_regen` 的 value 是**每秒百分比**，走 `pe.hpRegenPct`/`pe.manaRegenPct`，
  在 `_o()` 出口按 `maxHp*pct` 折成每秒量（和定值回复分开累加）。
- **装备栏有两套渲染，改一处不够**：`40-ui-8.js` 商店面板（`X.innerHTML`）和 HUD 状态栏
  `Q()`（`Z.el.innerHTML`）。两处判重都要从「id 变了」扩成「id 或数量变了」，否则用掉一个不重绘。
- 卡片副标题：消耗品没有 stats，`BB(stats,2)` 是空串，所以 `Z4()` 对消耗品走 `hS(active)`
  现场算「回血20% 移速+12%」——同样是数据生成，不手写。
- 消耗品没有"冷却"概念，详情卡不写 `冷却 N 秒`；上限写在 badge（`可叠加 3`）上。

## 关键经验：商店详情卡（`40-ui-8.js` 的 `qt()`）
- 结构：属性 → 被动 → 主动 → 合成路径，每块 `.sf-hud__dt-sec` 独立圆角小面板 +
  `.sf-dt-label` 极小型分区标签。**空块不渲染**，不写「无被动」。
- **面板窄（292u）时属性行必须单列**，两列会把「冷却缩减」「护盾效率」截成省略号。
- 商店面板高度上限 600u：低于这个值，主动装备的说明文字会被 `.sf-scroll` 折在折叠线以下。
  加高面板会让装备卡被 grid `1fr` 拉高、中部出现死空，用
  `.sf-hud__card-top { margin-top: auto }` 缓解。
- `herocheck` 的 `shotPanel(name)` 按运行时包围盒裁图；**别写死坐标**，改一次结构就框偏。
